# ADR 003 — No secrets in committed files, including examples

- **Status:** Accepted
- **Date:** 2026-10-13
- **Stated in:** [`docs/conventions.md#configuration`](../conventions.md#configuration), [`docs/architecture.md#configuration-and-secrets`](../architecture.md#configuration-and-secrets)

## Context

The repository runs on a case-insensitive filesystem (`core.ignorecase = true`) and its `.gitignore`
already covers `*.LocalSecrets.env`, `**/appsettings.Local.json`, `**/snapshots/**`, the
Playwright/Chromium binaries and build output.

A literal password in a committed example is a defect **even when the value is fake**: it teaches the
reader a pattern that violates the secrets policy. The same applies to connection strings, tokens and
API keys.

## Decision

- Secrets never appear in a committed file — **including examples, documentation, task files and
  fixtures**. A fake-looking literal is treated as a real leak, because it models the wrong behaviour.
- `appsettings.json` holds defaults only and contains **no secret fields**. Example configuration
  blocks show field names and non-secret values (host, port, database name), never credentials.
- Sources, by context:

  | Context | Source |
  |---|---|
  | Local development | User Secrets — `*.LocalSecrets.env`, gitignored |
  | Production | environment variables: `TOURSEARCH_DB_HOST`, `TOURSEARCH_DB_USER`, `TOURSEARCH_DB_PASSWORD`, `TOURSEARCH_DB_MAX_POOL`, `TOURSEARCH_SNAPSHOT_DIR` |
  | Integration tests | Testcontainers PostgreSQL — credentials generated by the container, nothing to commit |

- Ignore patterns stay deliberately narrow: `**/secrets`, `**/secrets.*` rather than `**/secrets*`,
  because the case-insensitive filesystem would let the latter silently ignore a real source file named
  `Secrets.cs`.

## Consequences

- Anyone cloning the repository gets a non-running app until they supply secrets — that is the intended
  trade-off, and it is why startup must **fail fast** on missing configuration
  ([`docs/runtime.md#startup`](../runtime.md#startup)) instead of half-starting.
- Reviews must reject example credentials, not just real ones. A "this is obviously fake" argument is
  not accepted.
- Configuration field **names** are safe to document; values are not.
- Contributing a new setting means documenting its name and its non-secret default, and adding the name
  to the table above — never an example value.
