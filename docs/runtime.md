# Runtime model

Status legend: [agents.md](./agents.md#status-legend).

## Processes

| Process | Type | Starts `BackgroundService` | Uses Playwright |
|---|---|---|---|
| `TourSearch.Api` | ASP.NET Core (Minimal APIs) | **no** | **no** |
| `TourSearch.Worker` | console executable | **yes — the only one** | yes |

Both share `Core` and `Infrastructure`. `Api` never links `Scraper` — see [architecture.md](./architecture.md).

## Startup

- **Api**: `RunApplication()` — DI graph: `AddInfrastructure()`.
- **Worker**: `RunApplication()` — DI graph: `AddInfrastructure()`, `AddScraper()`; `BackgroundService` is registered as a service that is resolved at startup, so its loop begins with the process.
- `[DECIDED]`: exactly one process starts a `BackgroundService`. If both did, the same job would be picked up twice.
- Startup must fail fast on a bad configuration (missing DB credentials, unknown region set) — not half-start and then loop doing nothing.

## Shutdown

- `SIGTERM` → `CancellationToken` fires → the worker stops between navigations.
- A worker may finish the **current** navigation only if it fits inside the supervisor's grace period; otherwise it **releases the lease** and exits. It must not "finish the job" past the grace period.
- Never swallow cancellation to complete work. Cancellation means "stop and let the lease expire".
- `main` must not block on `.Result` / `ThreadTask`; use `AsyncMain` and `await`.
- Exit codes: `0` clean shutdown, `1` bad configuration, `2` unrecoverable internal error (fail fast, the supervisor restarts).

## Playwright footprint

- `[FACT]` Playwright for .NET is the official port `microsoft/playwright-dotnet`. It requires an explicit install step — `playwright.ps1 install` downloads the browser binary into the app folder.
- In Docker: copy `playwright.ps1` into the image and run the install at **build** time. Never download the browser on the first request.
- One Chromium costs hundreds of MB of RSS.
- `[DECIDED]`: `MaxBrowsers = 1` per worker process. Scale by running several worker processes, not several browsers inside one process.
- Reuse the browser across jobs inside one worker; close it on shutdown.
- Memory guard: if RSS exceeds a configured limit, exit and let the supervisor restart the process.

## Restart semantics

The lease is what makes restarts safe:

1. The worker is killed mid-job → the lease is never released → the job stays `InProgress` with an expired `LeaseExpiresAt`.
2. On startup the worker runs a **recovery pass**: `InProgress` with `LeaseExpiresAt < now` → back to `Pending`, `Attempt + 1`, `ErrorCode = LEASE_EXPIRED`, `Retryable = true`.
3. The claim itself is an **atomic CAS** (`Pending → InProgress` writing `LeaseToken`, `LeaseExpiresAt`, `Attempt + 1` in one statement) — see [Job claim mechanism](./database.md#job-claim-mechanism). A read-then-write is not acceptable: two workers would take the same job.
4. The recovery query needs its own index — `(status, lease_expires_at)` — see [database.md](./database.md#index-rules). Without it every startup scans the whole table.
5. Without this pass a crash leaves a permanently stuck job that no TTL rule will rescue (see [database.md](./database.md#cleanup-ttl)).

## Ports and health

- **Api**: `GET /health` → `200` + server metadata (name, version, protocol revision). Used by MCP clients and by the supervisor.
- **Worker**: no HTTP endpoint. Its state is the job queue in the DB plus the logs.

## Configuration and secrets

| Context | Source |
|---|---|
| Production | env vars: `TOURSEARCH_DB_HOST`, `TOURSEARCH_DB_PORT`, `TOURSEARCH_DB_NAME`, `TOURSEARCH_DB_USER`, `TOURSEARCH_DB_PASSWORD`, `TOURSEARCH_DB_MAX_POOL`, `TOURSEARCH_SNAPSHOT_DIR` |
| Local dev | `LocalSecrets.env` at the repo root — gitignored; both it and `*.LocalSecrets.env` are covered in `.gitignore` |
| Integration tests | Testcontainers PostgreSQL — credentials generated by the container, nothing to commit |

Connection settings are read as **discrete variables**, never as one connection string: a single string
containing a credential is a value that can be accidentally committed or logged. The five `DB_*` names
above are **required** — `Host`, `Port`, `Name`, `User`, `Password` — and a missing one fails fast with an
error naming the variable (`[FACT]`, `DbConnectionSettings.FromEnvironment()`): startup must fail fast on
a bad configuration, not half-start and then loop. `TOURSEARCH_DB_MAX_POOL` and `TOURSEARCH_SNAPSHOT_DIR`
are read by other components, not by the connection settings.

Local development uses a single gitignored file at the repo root, `LocalSecrets.env`. Load it into the
shell before any command that reads the variables — including `dotnet ef`, which runs out of process:

```bash
set -a; . ./LocalSecrets.env; set +a
dotnet ef database update --project src/TourSearch.Infrastructure.Migration
```

`[FACT]` `.gitignore` must list **both** `*.LocalSecrets.env` and the bare `LocalSecrets.env`. A bare `*`
pattern does not match the bare name — `*.LocalSecrets.env` alone would leave `LocalSecrets.env`
committable, which is a credential leak into a public repository.

- `dotnet ef` runs the design-time factory in a **separate process**. It does not see the app's DI graph or its secret provider — it must read the same env vars exported in the shell.
- A committed example must never contain a literal password, even a fake one.
